|===
|Description
|Turning a set of source documents into a structured editorial summary.  
+
This module knows nothing about NewsAPI, and nothing about HTTP responses. It accepts `c.a.n.s.SourceDocument` rather than the news module's `c.a.n.n.Article` on purpose: that keeps news acquisition and summarization independent siblings instead of a chain, so either can be replaced without touching the other.
|Base package
|`com.arthur.newsbrief.summarization`
|Spring components
|* `c.a.n.s.SummaryGenerator` (via `c.a.n.s.internal.SpringAiSummaryGenerator` -- Produces summaries with a language model through Spring AI's `ChatClient`.  
+
The reply is requested as a typed `c.a.n.s.NewsSummary` rather than free text. Spring AI derives a JSON schema from the record, appends it to the prompt and parses the response back — so the model returns data, not prose that later code has to scrape.  
+
Prompts live in `resources/prompts` so wording can be tuned without a recompile, and reviewed as text rather than as escaped string concatenation.)
